Parcours Admin Achats

Ce n’est pas un cycle de vie produit (brouillon, valide, archive). C’est un comportement type : qui fait quoi, quand, et avec quels droits.

Exemple. Un Admin Achats doit ajouter des produits dont un attribut manque.

  1. Il va dans l’administration, cree l’attribut, choisit son type, ses contraintes et son groupe.
  2. Il importe le fichier qui porte les valeurs.
  3. Il verifie la liste : les produits sont la, le champ est visible dans le groupe.
  4. Il ouvre une fiche et complete les champs jusqu’a 100 % pour son perimetre.
RG-WF-00 — Les droits se lisent par groupe d’utilisateurs. L’Admin Systeme voit toute la completion. Les autres ne comptent que les groupes coches pour leur role. Aucune case = tout le monde.

Creation d’un produit

Objectif : enregistrer une nouvelle reference dans le referentiel.

Mermaid 
flowchart LR
  A[Liste - Nouveau produit] --> B[Saisir EAN, nom, categorie]
  B --> C[SAP facultatif]
  C --> D{Droits d'ecriture sur la categorie ?}
  D -->|Non| E[Refus]
  D -->|Oui| F[Fiche creee]
  F --> G[Completer les onglets]
  G --> H[Enregistrer]
RG-WF-01 — Sans droit d’ecriture sur la categorie, la creation est refusee. EAN, nom et categorie sont le minimum.

Modification d’un attribut d’un produit

Objectif : corriger une valeur (ex. couleur, remise) et tracer le changement.

Mermaid 
flowchart TD
  A[Liste ou recherche] --> B[Fiche produit]
  B --> C[Onglet du groupe]
  C --> D[Modifier le champ]
  D --> E[Champs calcules se mettent a jour]
  E --> F[Enregistrer]
  F --> G[Historique : ancienne / nouvelle valeur, utilisateur, date]
  D --> H[Quitter sans enregistrer]
  H --> I[Confirmation si modifications en cours]
RG-WF-02 — L’historique n’est ecrit qu’a l’enregistrement. Quitter la fiche avec des changements non sauves demande confirmation.

Forcer une valeur calculee

Objectif : ecarter exceptionnellement une formule (ex. PA interne). Priorite basse si complexite trop forte en cible.

Mermaid 
flowchart LR
  A[Champ calcule] --> B[Saisie manuelle]
  B --> C[Valeur forcee conservee]
  C --> D[Enregistrer]
  D --> E[La formule ne s'applique plus tant que le forçage n'est pas leve]
RG-WF-03 — Maquette Les champs calcules sont forcables. Cible A arbitrer : conserver un levier d’exception, avec trace.

Activer un canal de publication

Objectif : rendre le produit actif sur Optic 2000 (O) et/ou Lissac (L).

Mermaid 
flowchart TD
  A[Onglet Informations generales] --> B[Actif canal O / Actif canal L]
  B --> C{Au moins un canal actif ?}
  C -->|Oui| D[Statut de publication = Oui]
  C -->|Non| E[Statut de publication = Non]
  D --> F[Date de MAJ du statut si le statut change]
  E --> F
  F --> G[Enregistrer]
RG-WF-04 — Le statut de publication n’est pas saisi : il se deduit des canaux. La date de MAJ statut ne bouge que si le statut change.

Ajouter un fournisseur / une condition commerciale

Objectif : enregistrer un accord (marque × fournisseur × type × segmentation).

Mermaid 
flowchart TD
  A[Administration - Conditions commerciales] --> B{Fournisseur connu ?}
  B -->|Non| C[Creer le fournisseur]
  B -->|Oui| D[Nouvelle condition commerciale]
  C --> D
  D --> E[Marque, type, segmentation]
  E --> F[RF, RFA, remise interne, reprise, livraison]
  F --> G[Enregistrer la ligne]
  G --> H[Les fiches produits correspondantes peuvent reprendre l'accord]
RG-WF-05 — Une nouvelle marque tapee ici (ou sur une fiche) enrichit le referentiel unique de marques.

Creer un attribut

Objectif : etendre le modele sans deploiement (parametrage).

Mermaid 
flowchart TD
  A[Administration - Attributs] --> B[Nouvel attribut]
  B --> C[Libelle, identifiant, type de saisie]
  C --> D[Groupe d'accueil]
  D --> E[Obligatoire ? Qualite / completion ?]
  E --> F{Formule, masque, liste de valeurs}
  F --> G[Enregistrer]
  G --> H[L'attribut est disponible a la saisie, a l'import et a l'export]
  H --> I[Eventuellement le rattacher a d'autres groupes]
RG-WF-06 — L’identifiant ne se change plus une fois utilise dans des fichiers d’echange. Un attribut systeme n’est pas cree par ce parcours.
